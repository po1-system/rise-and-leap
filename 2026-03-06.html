Executive Summary

今回の要点

OpenClawを実際に動かし、品質・モデル・費用を選ぶ開発段階へ。

健太郎さんがOpenClawの初期環境を構築し、最初の自動処理を実行した。一件あたりのAPIコストを算出したことで、処理ごとにモデルを使い分け、無駄な工程を削減する必要性が明確になった。次の段階ではスプレッドシートとLINE WORKSを接続し、エラー対応を含む実運用へ進む。和雄さんは応募数を追う段階から、不審案件の除外、不採用分析、自分の考えを入れた提案へ移行。研究会全体では、各メンバーの専門知識をOpenClawへ集約し、2026年末に一人で十人分の労働力を提供する年間ロードマップが共有された。

Discussion

主な議論

初回実行、応募品質、知識基盤、年間実証計画へ広がった44の論点。

Goal

PMという年間目標を再確認

1〜3月は応募・返信・テスト・分析の土台を作り、4月以降は中価格帯、進行、顧客対応の実務へ進む。

Health

生活に合う計画へ直す

遅番翌朝の早朝予定、睡眠不足、代替案の欠如を見直し、勤務シフトと体調に合わせて再設計する。

Foundation

自己管理を業務基盤にする

案件発見、テスト、納期、会議を実行する前提として、睡眠・体調・生活の安定を位置づける。

Quality

応募数だけを埋めない

数字を追いつつ、応募理由、相性、不採用後の分析を持ち、受注へつながるかを判断基準にする。

Thinking

AIに自分の考えを渡す

応募理由、経験、顧客ニーズ、懸念、成果を本人が言語化し、AIを思考を引き出す質問役にする。

Filter

不審案件を人間が先に除外

矛盾、本人確認、外部誘導、勧誘、報酬の不自然さを見抜き、AI時間・トークン・準備時間を減らす。

Response

返信とテストへ進み始める

顧客対応、セールス、動画台本、仮払い待ちなど、無反応から次選考へ進む状態へ変化した。

Review

テスト不通過を分析する

回りくどさ、直接回答、簡潔さ、顧客意図を仮説として記録し、失敗を次のテストへ接続する。

Channels

応募媒体を拡大する

Lancers・CrowdWorksに加え、Indeed・Wantedlyのプロフィールを整え、案件種類と単価の幅を広げる。

Writing

noteを言語化訓練として継続

直ちに集客へつながらなくても、継続、文章構成、自己理解、発信習慣の価値を残す。

Roadmap

OpenClawをフェーズ化

0.5の最小動作、1.0のデータ・連絡接続、1.5のエラー処理と安定化へ段階的に進める。

Minimum

完全自動化を最初から狙わない

まず一つの処理を動かし、そこから安定性、精度、範囲、人間作業の削減を広げる。

First Run

OpenClawを初めて実行

必要環境を準備して最初の自動処理を動かし、構成調査から処理結果を検証する段階へ移った。

Substance

見えるデモより結果を優先

Macでの画面可視化に固執せず、実行ログ、成功・失敗、コスト、データ連携を本質とする。

Measurement

APIコストを初めて実測

Claude Sonnet系の入力・出力から一件約0.52円を試算し、大量処理時の費用を現実の設計条件にした。

Routing

高性能モデルを選んで使う

複雑な判断・文章は高性能、抽出・分類・重複除去・形式変換は軽量モデルへ分ける。

Preprocess

処理そのものを減らす

対象外の事前除外、重複入力の回避、必要部分の抽出、要約再利用、人間の即時判断で費用を抑える。

Database

Sheetsと接続する

タスク、条件、URL、状態、結果、エラー、コスト、承認を記録し、処理の現在地を一覧化する。

Interface

LINE WORKSを窓口にする

人間の依頼、OpenClawの実行、Sheets記録、結果返却を日常のチャットからつなぐ。

Errors

エラー処理を次の壁に

画面変更、ログアウト、API停止、形式差、タイムアウト、途中終了、重複を検知・再実行・報告する。

Knowledge

新しい事例を共有する

他メンバー、社会の事例、技術情報、実エラー、モデル・API変更を集め、開発視点で検証する。

Communication

開発の短時間対話を増やす

週一定例だけでなく、目的、処理、エラー、実装、優先順位を短い周期ですり合わせる。

Hardware

端末はメモリを重視

複数アプリ、ブラウザ、Docker、コンテナ、データ処理を同時に動かす用途から必要性能を決める。

Cooling

AirとProを用途で選ぶ

文章・探索中心ならAir、OpenClawやDockerの長時間高負荷なら冷却のあるPro・デスクトップを検討する。

Displays

画面数からMacを選ぶ

外部モニター数と最大メモリを実際の使い方から決め、単純に上位モデルを選ばない。

Collective

知見をOpenClawへ集約

戦略、求人、動画、地域、AI、改善、開発の専門性を、再利用できるルールとデータとして蓄積する。

Individual

交流より個人目標へコミット

直接交流を目的にせず、各自の課題と行動に集中し、成果となった知識を全体で使える形にする。

Members

新しい専門メンバーが加わる

非公開求人と戦略コンサルの知見が加わり、実績後の案件接続と上流思考を補強する。

Strategy

戦略知識をAIへ入れる

顧客分析、課題仮説、会議目的、質問、提案、リスク、次行動をAIと事前準備できるようにする。

Context

現場情報は人間が集める

空気、反応、文化、背景、暗黙知を取材・対話・観察で集め、AIへ渡す人間の役割を残す。

Local

地域活動へAIを接続

市民の声を集め、課題整理、施策案、動画発信、地域還元へつなげる民間の活動モデルを考える。

Year Plan

一年の段階を定める

春の調査、初夏の部分導入、夏の業務圧縮、秋の受注拡大、12月の十人分労働力へ進む。

Purpose

From Previous

前回からの変化

安全な導入思想から、実測に基づく開発と一年の実証計画へ。

2月27日は、Docker隔離、並列処理、費用上限、人間承認、ルールブックによりOpenClawを安全に導入する思想を固めた回だった。3月6日には初期環境で最初の処理が動き、一件あたりのAPI費用が実測された。研究は可能性の議論から、処理結果、モデル選択、費用、データ連携、エラー対応を改善する開発へ移った。和雄さんの案件活動も、件数から不審案件の除外、不採用分析、本人の考えを含む提案へ進化。同時に、研究会の専門知識をOpenClawの分身として蓄積し、春の調査から冬の十人分労働力実証へ進む年間ロードマップが示された。

Historical Position

歴史的な位置づけ

OpenClawが初めて現実に動き、研究会の知識基盤として育てるロードマップが確立した回。

2月20日の可能性発見、2月27日の実運用思想を経て、この回でOpenClawは初めて処理を実行し、費用と結果を記録できる対象になった。動かしたことで、最新モデルが常に最適とは限らず、大量処理では小さな単価差が積み上がり、画面デモよりログと結果が重要で、データベース、チャット窓口、エラー処理が本番運用の鍵になると分かった。また、研究会メンバーが増える目的は人脈ではなく、求人、戦略、動画、地域、AI、開発の知識を専門エージェントとして蓄積することへ変わった。活動は一週間単位の実験から一年の実証プロジェクトへ進み、後のOpenClaw／PO1におけるフェーズ管理、実行ログ、費用管理、モデルルーティング、知識ベース、専門エージェント、承認フロー、組織展開の原型となった。

From a first run to a shared intelligence.一つの実行から、研究会全体の知識基盤へ。
